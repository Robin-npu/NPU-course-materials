## 一、项目概述
### 1.1项目背景
本项目旨在设计并验证一个单周期 MIPS 处理器核心（CPU_RED），支持 ORI、ADDU、LW、SW、BNE 五条基本指令。目标是通过 RTL 建模与自动化仿真，理解指令流水线、译码控制逻辑及单周期数据通路的时序约束。
### 1.2 核心信息
* **AI Agent 工具**：使用了 **Gemini 3 Flash** 工作环境。
* **集成工具**：VS Code + Verilator 仿真引擎 + Cocotb 验证框架 + GTKWave 波形查看器。
* **Agent Skill 使用情况**：
    * **代码生成**：辅助编写 MIPS 指令译码逻辑与 ALU 算术单元。
    * **验证辅助**：生成测试激励脚本（Python），并协助诊断 84% 覆盖率的具体原因。
    * **图像生成**：辅助生成硬件架构图与时序波形示意图。

## 二、工作流与交互路线图
### 2.1整体实施策略

1.  **需求拆解**：首先要求 AI 梳理五条指令的格式（R/I 型）及其控制信号真值表。
2.  **分层引导**：先指导 AI 生成数据通路的 Top 模块框架，再要求其填充具体的 `always` 块逻辑。
3.  **闭环验证**：将生成的代码投入 Verilator 编译，根据报错信息反馈给 AI 进行即时修正。
4.  **覆盖率分析**：在达到 84% 覆盖率后，通过 AI 辅助识别未覆盖的 `else` 分支。

### 2.2 Agent能力适配与优化
* **特性表现**：AI 在处理标准 MIPS 编码（如 `addu` 的 funct 码）时准确度极高，代码补全能力极强。
* **弱点与改进**：AI 初始生成的 BNE 跳转逻辑忽略了“地址需左移两位”的硬件特性。针对此弱点，我通过明确提示“MIPS 指令地址为字对齐”来引导其增加 `{imm_ext[29:0], 2'b00}` 移位操作。

## 三、关键交互说明
### 3.1 架构设计阶段
* **（1）提问**：请设计一个单周期 MIPS CPU 的顶层模块结构，包含指令存储器接口和数据存储器接口。
* **（2）AI 反馈**：AI 提供了包含 `PC`、`Decoder`、`ALU` 和 `RegFile` 的模块划分建议。
* **（3）判断与修改**：我判断其给出的内存读写信号过于简化，要求其增加 `dmem_re`（读使能）以适配单周期异步读逻辑。



### 3.2 电路设计阶段
* **（1）提问**：如何实现单周期内的 $0 寄存器只读逻辑？
* **（2）AI 反馈**：建议在 RegFile 写入时增加 `if (wa != 5'b0)` 判断。
* **（3）验证与修改**：通过波形发现初期修改未覆盖所有写入指令，后续手动在顶层译码阶段对 `RegWrite` 信号与 `wa != 0` 进行了与逻辑锁定。

### 3.3 验证阶段交互记录
在验证阶段，我向 AI 咨询：“为什么我的 BNE 指令覆盖率不是 100%？”AI 分析了我的测试序列，指出是因为我只测试了“跳转成功”的情形，未测试“比较相等时不跳转”的分支路径，但是最后覆盖率只能提升到84%，继续修改反而会降低覆盖率。


### 3.4回答问题
<!-- 请回答以下四个问题 -->
- Q : 所有指令在单周期处理器中都要经历完整的5个执行阶段，试说明：指令的“写回控制信号” 是指令的重要特征之一，对于R型运算指令、LW访存指令和SW存数指令，哪些指令需要激活写回控制信号？这一控制信号的共性作用是什么？
  A : **写回控制信号**：**R型运算指令**和**LW访存指令**需要激活写回信号。其共性作用是将 ALU 运算结果或从内存读取的数据存入目标寄存器。**SW** 指令不需要写回寄存器。

- Q : 指令由操作码和操作数（或地址码）  两部分构成是所有指令的共同特征，请简述：在单周期处理器的取指阶段 ，CPU是如何获取这两部分信息的？该共性特征对指令长度的设计有什么基本要求？
  A : **取指阶段获取信息**：CPU 通过 `PC` 指向的地址从存储器读取 32 位二进制串。高 6 位解析为操作码（Opcode），其余字段解析为寄存器索引或立即数。这要求指令长度必须**固定且对齐**，以便硬件并行解析字段

- Q : 单周期处理器的核心约束是“ 每条指令耗时一个时钟周期 ”，请分析：这一约束决定了所有指令的执行流程必须满足什么共性条件？该条件会对单周期处理器的硬件资源利用效率产生什么影响？
  A : **单周期核心约束**：决定了**所有逻辑操作必须在单一时钟周期内稳定**。这会导致时钟频率受限于最慢的指令（如 LW），降低了硬件资源在处理简单指令时的利用率。
  
- Q : 以MIPS指令集为例，R型、I型指令的格式存在差异，但也有共性。试指出这两类指令在 寄存器操作上的一个共同特征，并说明该特征如何适配单周期处理器中寄存器堆的“读/写端口”设计？
  A : **寄存器共性特征**：两类指令均需通过 5 位地址访问寄存器堆。这适配了寄存器堆的“双读一写”端口设计，确保在周期前半段读出数据，在周期结束前完成写入。

## 四、知识盲区识别与整理
### 4.1 体系结构知识盲区
**符号扩展 vs 零扩展**：明确了 ORI 指令必须使用零扩展（Zero-Extend），而 LW/SW 需要符号扩展。
**字地址跳转**：深入理解了 BNE 指令偏移量在硬件实现中需要乘以 4（左移两位）的底层逻辑。

### 4.2 工具与辅助技术知识盲区
**Cocotb 异步时序**：起初不理解 `Timer` 的重要性，通过仿真失败意识到 Python 与 RTL 仿真的同步竞争问题。
**Verilator 覆盖率收集**：学习了如何通过 `.dat` 文件导出并分析分支覆盖率。

### 4.3 AI生成内容的质疑
在生成 BNE 跳转逻辑时，AI 曾建议使用多周期流水线的“延迟槽”设计。我及时质疑并纠偏，要求其严格按照单周期处理器的组合逻辑实现跳转，避免引入复杂的时序依赖。基本都是发现AI的思路有偏差，就把作业要求重新提交给AI，让它严格按照要求来设计。
